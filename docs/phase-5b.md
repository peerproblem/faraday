# Faraday Phase 5b UI 전환 및 검수

## 결정

Faraday의 UI 컴포넌트는 `@sw3/ui`를 표준으로 삼는다. Vercel UI SDK를 계속 사용해야 하는 별도 조건은 없다. **컴포넌트 교체는 진행 중인 10개 fork의 통합이 완료된 뒤 Phase 5b에서 시작한다.** 통합된 `components/ui`에서 키보드·접근성 검수를 통과한 컴포넌트부터 실제 SW3 컴포넌트로 교체한다. 미통과 또는 미지원 항목은 기존 구현을 임시로 유지하고 재검수 항목을 남긴다.

SW3의 코너 스무딩과 에이전트 연동은 실제 컴포넌트를 렌더해 적용한다. `SwProvider`, `sw-root`, `@sw3/ui/styles.css`를 연결하고 보드 단위 WebMCP 등록에서 같은 도구가 중복 노출되지 않는지 확인한다. README의 `built on Vercel's UI SDK` 문구는 실제 전환 상태에 맞춰 갱신한다.

두 기준의 패키지 버전은 모두 `0.1.0`이다. `client/vendor`에 서로 다른 파일명으로 보관하고 lockfile이 해당 tarball을 가리키는지 확인한다. v2는 브랜치가 이동해도 위의 전체 커밋 SHA로 빌드한다.

## 통합 직후 준비

- [ ] 통합 커밋을 기록하고 `client/src/components/ui`의 export와 위젯의 import를 대조해 아래 검수표를 갱신한다. 검수표의 초기 범위는 통합 전 보드와 Studio 화면을 기준으로 한다. [Faraday 기준 커밋](https://github.com/peerproblem/faraday/tree/01406eb0241b21f4108cae790839e82dc34f8f00)
- [ ] 위에 고정한 SDK 기준에서 sync 스크립트로 빌드·패킹하고 `client/vendor`의 tarball과 lockfile을 검증한다. 생성된 `registry.json`을 tarball과 동일한 커밋에서 사용한다.
- [ ] `registry.json`의 규칙을 위젯 스키마와 생성·수정 프롬프트에 반영한다. 예를 들어 `Stat`은 한 줄에 최대 5개를 배치하고 초과분은 다음 줄에 표시한다. 서버와 클라이언트의 `BoardSpec`, 생성 프롬프트, 보드 렌더러에서 보드별 `accent`를 제거한다. 기존 `accent` 값을 담은 저장 보드와 스트리밍 중인 부분 스펙도 열어 본다. `warning` 같은 상태는 텍스트로 전달하고 강조색은 SW3의 파란색을 사용한다.
- [ ] 동일한 Next 16 환경에서 교체 전후 `npm run build`와 `npm run start`를 실행한다. `/`, `/studio/[id]`, `/b/[slug]`에서 직접 로드와 클라이언트 이동을 확인한다. 각 경로의 초기 JS와 지도 지연 로드 청크 크기를 동일한 방식으로 비교해 기록한다. hydration 오류, 지도 워커·스타일 로딩 실패, 배포 환경에서의 tarball 설치 실패가 있으면 해당 변경을 보류한다.

## 모든 컴포넌트의 통과 기준

- [ ] 실제 Faraday 화면에서 마우스 없이 `Tab`과 `Shift+Tab`으로 들어오고 나간다. 초점 순서는 읽는 순서와 일치하고, 밝은·어두운 테마에서 초점 표시가 스크롤 영역이나 오버레이에 가려지지 않는다. 정적 요소를 불필요하게 탭 순서에 넣지 않는다.
- [ ] 접근성 트리와 스크린리더로 이름·역할·값·상태를 확인한다. 시각적 레이블, 선택, 경고, 오류, 결과가 낭독 내용과 일치한다. 색이나 마우스 호버에만 의존하는 정보가 없다.
- [ ] 해당 화면의 로딩·빈 상태·오류·실시간 갱신을 재현한다. 갱신 중 사용 중인 입력과 초점이 유지된다. 초점이 있던 항목이 사라지면 같은 위젯의 다음 제어 요소나 위젯의 시작점으로 이동할 수 있다.
- [ ] 적용되는 항목을 모두 통과한 경우에만 교체한다. 결과는 `대기`, `통과`, `보류`로 기록한다. `보류`에는 재현 순서와 실패한 동작을 적고 기존 구현을 유지한다.

## 컴포넌트별 체크리스트

| 컴포넌트와 검수 화면 | 키보드 통과 기준 | 접근성 통과 기준 |
| --- | --- | --- |
| `Button` · 보드 만들기, 예시 프롬프트, Studio 수정·게시, 보드 새로고침 | `Enter`·`Space`로 작업이 한 번 실행된다. 예시 버튼은 입력만 채운다. 처리 중 반복 입력으로 중복 요청이 생기지 않는다. | 동작이 드러나는 이름이 있고, 비활성 또는 처리 중 상태와 성공·실패를 알 수 있다. 아이콘 전용 버튼에는 접근 가능한 이름이 있다. |
| `Field` / `Label` / `Textarea` · 생성·수정 프롬프트 | 전후 필드로 `Tab` 이동이 된다. `Enter`는 줄바꿈한다. 생성 화면의 `⌘/Ctrl+Enter`는 유효한 입력만 한 번 제출하며 한글 IME 조합 중에는 제출하지 않는다. | 레이블·도움말·오류가 입력과 연결된다. 실패 시 입력값을 유지하고 사용자가 수정할 곳과 이유를 알 수 있다. |
| `Tabs` · Studio 패널 | 탭 목록은 한 번만 탭으로 진입한다. 방향키로 이동하고 `Home`·`End`가 동작한다. 수동 활성화라면 `Enter`·`Space`로 선택한다. | 목록·탭·패널의 관계와 선택 상태가 올바르다. 숨겨진 패널의 컨트롤은 탭 순서에서 빠진다. |
| `Select` · 타임라인 필터 | `Enter`·`Space`·방향키로 열고, 방향키로 이동해 `Enter`로 선택한다. `Esc`로 취소하면 이전 값과 트리거 초점이 유지된다. `Tab`으로 다음 요소에 간다. | 필터 이름, 선택값, 펼침과 강조 옵션 상태가 읽힌다. `All events`와 `Major events only` 전환 후 목록과 0건 상태를 확인할 수 있다. |
| `Timeline` · 사건 목록 | 방향키로 항목 간 이동이 되고, 각 항목의 인용 칩에 `Tab`으로 도달한다. 필터·갱신 뒤에도 탐색을 이어갈 수 있다. | 제목·시간·설명·중요도를 읽을 수 있다. 날짜 미상도 텍스트로 전달한다. 중요도를 마커 색에만 담지 않는다. |
| `Accordion` · 공식 경보, `Collapsible` 후보 · 출처 목록 | `Enter`·`Space`로 열고 닫는다. 열린 패널의 공식 공지 링크·인용 칩으로 이동할 수 있다. | 제목과 펼침 상태가 연결되어 읽힌다. 닫힌 패널의 링크는 탭 순서에서 빠진다. 경보 등급과 발행 기관을 읽을 수 있다. |
| `Popover` / 인용 칩 · 요약, KPI, 타임라인, 표, 경보 | `Enter`·`Space`로 열어 원문 링크까지 이동한다. `Esc`로 닫으면 해당 칩으로 초점이 돌아온다. 비모달 팝오버 밖으로 `Tab` 이동이 된다. | 칩 이름에 출처를 식별할 정보가 있다. 제목·발행처·원문 링크를 읽을 수 있고, 참조가 누락된 출처는 빈 버튼을 남기지 않는다. 전용 칩 전환은 후보 구현이 준비될 때까지 보류한다. |
| `Tooltip` · 보드 새로고침 | 트리거에 초점이 오면 열리고 `Esc`로 닫힌다. 초점은 트리거에 남는다. | 버튼의 이름과 동작은 툴팁을 닫아도 알 수 있다. 추가 설명이 중복 낭독되지 않는다. |
| `Meter` · 보드 심각도 | 읽기 전용 표시이므로 탭 순서에 추가되지 않는다. | `Severity` 이름과 현재 값·범위가 읽힌다. 예를 들어 `3/5`의 의미를 막대 색에 의존하지 않고 파악할 수 있다. |
| `Badge` · 보드 상태, 경보 등급 | 상태 표시는 탭 순서에 추가되지 않는다. | `Live`, `Offline`, `Warning` 등의 실제 상태가 텍스트로 전달된다. `warning` 표현이 필요한 슬롯은 후보가 준비될 때까지 기존 구현을 사용한다. |
| `Stat` · KPI | 값 자체는 탭 순서에 추가되지 않고 연결된 인용 칩은 조작할 수 있다. | 지표 이름, 값, 단위, 변화량, 경고를 함께 확인할 수 있다. 6개 이상의 지표가 있어도 한 줄에 5개 이하로 배치된다. 경고 톤이 필요한 슬롯은 후보가 준비될 때까지 기존 구현을 사용한다. |
| `Toast` · 새로고침·갱신 알림 | 알림이 현재 초점을 빼앗지 않는다. 액션·닫기 버튼이 있으면 키보드로 조작할 수 있다. | 처리 결과가 한 번 읽힌다. 실시간 이벤트가 연속 도착해도 보드 전체를 반복 낭독하지 않는다. 오류 원인은 읽을 수 있는 상태로 남는다. |
| `Table` · 도로 통제, 자원 등 표 위젯 | 가로로 넘치는 표를 키보드로 스크롤할 수 있고 영역을 빠져나올 수 있다. 정렬이 있는 경우 헤더의 버튼으로 실행하며 초점이 유지된다. | 표 이름과 열·행 헤더 관계가 읽힌다. 정렬이 있는 경우 현재 방향이 전달된다. SW3 `Table`이 준비될 때까지 기존 HTML 표를 유지한다. |
| `MapView` · 지도와 유형별 마커 | 키보드로 지도에 들어오고 나올 수 있다. 확대·축소와 마커 상세가 핵심 동작이면 키보드로 실행하거나 동일한 정보를 목록에서 얻을 수 있다. | 지도 제목과 위치 목록에서 이름·유형·상세를 읽을 수 있다. `impact`, `incident`, `shelter`, `closure`, `resource`, `origin`을 색으로만 구분하지 않는다. 여섯 유형을 표현할 수 있을 때까지 기존 지도를 사용한다. |
| `Skeleton` / 빈 상태 · 보드 생성, 필터, 지도, 출처 | 자리표시자는 탭 순서에 들어오지 않는다. 결과가 도착해도 현재 초점을 빼앗지 않는다. 재시도 버튼이 있으면 키보드로 실행된다. | 로딩·결과 없음·오류가 구분되며 장식용 자리표시자는 낭독되지 않는다. 관련 변경만 알린다. 전용 컴포넌트가 준비될 때까지 기존 구현을 사용한다. |
| `ChartCard` + 차트 · 통합 후 차트 위젯이 포함된 경우 | 범례·범위 선택처럼 실제 동작이 있는 제어 요소에 도달한다. 호버에서만 보이는 핵심 수치는 표나 텍스트에서도 확인할 수 있다. | `ChartCard`로 감싸고 차트에 내용과 단위를 설명하는 `aria-label`을 준다. 계열은 색 외에 레이블이나 패턴으로도 구분한다. |

요약·도움말·뉴스·변경 로그·출처 위젯도 통과 기준을 적용한다. 링크의 읽는 순서, 고유한 이름, 표시된 출처와 실제 링크의 일치를 확인한다. 지원되는 브라우저에서 WebMCP `snapshot`과 `act()`로 전환된 상호작용 하나씩을 확인하고 키보드 조작과 상태가 일치하는지 본다.
